# 架构与开发约束

## 四层结构

页面与组件 → Server Actions / Route Handlers → 业务服务与权限检查 → Prisma / 私有文件 / SMTP。

Next.js App Router + TypeScript；Tailwind CSS + shadcn 风格组件；Better Auth 的邮箱认证、数据库会话与令牌；Prisma 7 + SQLite；Zod；Nodemailer；Mailpit。依赖由 package-lock.json 固定，使用 npm ci 复现。

## 界面主题

全局 CSS 语义变量覆盖浅色与暗色；主题通过根节点 `data-theme` 控制。`public/theme-init.js` 在首屏渲染前读取浏览器偏好，默认跟随系统；客户端 `ThemeSwitcher` 管理手动选择、系统变化及跨标签页同步。主题状态不参与认证与权限。品牌透明图位于 `public/brand`（静态设计资产，非上传文件），CSS 遮罩提供深浅着色及暗色闪光，并尊重 `prefers-reduced-motion`。

## 认证与授权

Better Auth 管理 User 的认证字段、Account、Session、Verification 和 RateLimit。自定义角色与状态字段均为 input:false，公共注册数据库钩子强制 MEMBER/PENDING，并创建入会申请。后端每次获取会话后重新读用户数据库，不启用 Cookie 会话缓存。

`policy.ts` 为纯权限规则；`session.ts` 负责真实会话与页面守卫。权限在入口和业务服务检查，后台布局检查不能替代子页面或操作的检查。页面不以客户端传来的角色、状态或作者为判断依据。通过 library 的原始 signup 路径创建的账号也只能是待审批成员。

初始管理员密码使用 Better Auth 的密码散列器创建，保留 credential Account 模型。首次改密标志只在认证库确认改密成功后清除；新密码不得与当前密码相同。账号停用、管理员角色改变和密码重置都撤销相关旧会话。

离线账号恢复是服务器维护工具：`reset-super-admin-server.sh` 使用现有升级锁，暂停网站及项目 worker，调用 `reset-super-admin.mjs`。后者只打开指定的现有数据库，使用 Better Auth 的 `hashPassword`，通过 SQLite 备份接口建立只含数据库的私有恢复点；再次检查唯一超级管理员及其 ACTIVE / 已验证状态、唯一 credential 账号后，以同一写事务更新散列、撤销会话与密码重置 Verification、设置改密标志并写审计。失败回滚，维护脚本恢复原先运行的服务。该入口不读取初始化密码，不开放 HTTP 路由；只在交互终端隐藏输入两次新密码。

管理员邀请码在服务端以 SHA-256 摘要匹配，绑定邮箱。邮箱验证回调尝试激活关联邀请；过期或撤销时不授予身份。已有成员在登录后可主动兑换。邀请码消耗、身份激活、审批状态更新和审计日志同一个事务提交，条件更新保证最多消费一次。

## 数据与文件

用户与审批申请为一对多，保留申请历史；邀请绑定创建者；资料关联分类、标签、作者与唯一 StoredFile；帖子分类独立。评论、回复用 parentId 表示两层，业务服务校验主题与层级。

公开资料查询用显式 DTO，不返回邮箱、存储键或讨论。内部讨论先授权再查询；相关页面动态渲染，API 与下载为 private/no-store。上传需要同源请求及当前成员身份，流式保存，文件数量、字段、大小和常见文件签名均检查。文件保存后才写资料记录，失败清理文件；实际资料区在写入前校验。

原始文件名只用于显示和附件文件名，存储键是随机 UUID，路径解析只接受 UUID。下载通过资料 ID 查询未删除的资料，重新检查当前用户，并以 application/octet-stream + attachment + sandbox/nosniff 返回。资料 ZIP 不解压。存储接口为 saveUpload / read / remove，可替换为对象存储；项目 ZIP 导入使用独立的临时存储和解包流程。

SQLite 地址在 CLI 和运行时均按项目根目录解析，避免指向不同数据库。初始化先创建 SQLite 文件以兼容 Windows 数据库工具。分类、角色等数据库字符串的业务枚举必须在入口校验。

## 主要入口

- `/api/auth/[...all]`：认证库路由；附加停用登录和首次改密保护。
- `POST /api/account/register`：普通或邀请注册；保留认证库限流与同源检查。
- `POST /api/resources`：一份文档或一组图片与 title/description/area/categoryId/tagIds，多部分上传。
- `GET /api/resources/:id/download`：授权附件下载。
- `GET /api/discussions/:kind/:id`：内部讨论只读接口，kind 为 RESOURCE 或 POST。
- `src/app/actions.ts`：成员审批、重申、管理员管理、资料编辑删除、发帖、留言、分类与审计入口。
- `POST /api/projects`：200MB 项目 ZIP 与介绍信息，检查当前成员后持久化同步任务，返回 202 与项目 / 任务 ID。
- `GET /api/projects/:id/status`：仅作者 / 管理员读取同步状态；`files` / `file` / `download` 为成员专享的指定版本访问。
- `GET/POST /api/projects/:id/discussions` 与 `/api/project-images/:id`：私有项目讨论及图片。
- `src/app/project-actions.ts`：项目介绍修改、项目 / 留言删除及任务重试。
- `/api/resources/:id/questions`：PDF 问题查询、提问、回复、解决状态与删除；所有入口先检查当前成员和具体文件关系。

正式错误不输出数据库结构、令牌或文件路径；表单失败保留输入。纯文本和 Office 提取内容由 React 转义，禁止直接渲染用户 HTML。

## 私有媒体扩展（2026-10-10）

保留 Resource.fileId 主文件以兼容旧资料。新增 Attachment 关联其余资料图片及帖子、评论、回复图片；每条附件只归属一种内容，fileId 唯一，迁移 SQL 的 CHECK 约束保证唯一父内容。新迁移仅建表，不重写旧记录。

saveUpload 流式接收最多 20 个文件，累计文件实际字节数，执行 50×1024×1024 总量检查，并限制整个 multipart 请求与字段大小。图片逐个检查扩展名和签名；混合文档上传拒绝。解析或业务事务失败时清理本批上传的全部文件。图片上传使用 Route Handler，避免 Server Action 的正文大小限制；长上传结束后重新读取会话及账号状态。

resourceFile 与 attachmentFile 统一检查当前成员权限、资料/主题/留言及父留言删除状态。GET /api/resources/:id/download?fileId=... 和 /preview?fileId=... 只接受该资料所属文件；无 fileId 时保持旧主文件入口。GET /api/attachments/:id 返回授权图片，私有接口均 no-store、nosniff、CORP same-origin。图片使用原始 img，绕过公共图片优化缓存；PDF 通过授权 fetch 交给浏览器端 PDF.js Worker，按页绘制 canvas，不执行 PDF 脚本或打开外链；阅读器程序与字体映射由本项目提供，预览响应仅允许同源嵌入，其他页面仍 DENY。非图片/PDF 内容保持附件类型，通过授权 fetch 获取后渲染纯文本。

Office / ZIP 在浏览器动态加载 fflate：只解压所需 Office XML（合计最多 10MB），最多 1000 个 ZIP 条目；目录预览不解压文件。DOMParser 不插入 HTML，拒绝 DOCTYPE/ENTITY，所有文本由 React 转义。不获取外链、执行宏或重算公式。服务器不安装 Office 转换服务。

帖子编辑在同一事务中检查归属、已有图片与新增图片的数量和字节总量，移除关联、追加图片及写审计。移除和软删除后的文件保留于私有存储，旧媒体入口拒绝访问，备份仍复制整个目录。

### 专业项目与远端存储

继续采用页面与组件 → 服务端入口 → 业务服务 / 权限 → 基础设施分层。GitHub 接口独立封装，业务服务不散落 HTTP 调用。项目、版本与同步任务记录留在 SQLite，记录不可变的提交 SHA、文件清单及校验结果；浏览和下载按指定提交读取，避免分支变化使版本对应错误。

GitHub App 仅在服务器使用，安装在专用组织，配置仓库创建及内容写入所需权限；私钥和访问令牌不返回浏览器、不输出日志、不进入项目包。组织配置属于服务器配置；本次不新增普通成员可操作的授权管理界面。不授予成员绕过网站鉴权的 GitHub 仓库访问。

项目 ZIP 先流式暂存到私有临时目录。压缩包实际字节和实际解压累计字节分别限制 200×1024×1024；单文件限制 100×1024×1024，最多 1000 个条目（包括显式目录），超过任一边界立即停止并清理临时文件。所有文件都计入解压总量，包括不会导入的文件，不仅依赖 ZIP 头部声明的大小。项目导入与资料 ZIP 目录预览是独立流程；yauzl 逐条读取，校验路径、链接、重复路径、目录冲突、实际尺寸与 CRC，再把可导入的内容写到 UUID 任务目录中的固定编号文件。原路径只进入清单和远端文件目录，不直接用作磁盘写入路径。过程不执行文件、构建指令或工作流。

`Project`、`ProjectVersion`、`ProjectSyncTask`、`ProjectComment` 与专用图片关联记录留在数据库；版本保存提交 SHA、文件清单和校验摘要。`project-storage.ts` 负责上传与安全解包，`github-projects.ts` 提供创建仓库、发布快照、列出 / 读取文件和下载版本接口，`projects.ts` 管理成员与归属规则，`project-worker.ts` 执行同步状态机。独立 `npm run projects:worker` 进程串行执行任务，数据库租约防止重复 worker 同时发布；请求 UUID、稳定仓库名、任务引用和 taskId 唯一版本记录保证重试幂等。

200MB 上传走专门的项目 Route Handler，文件正文限额与 multipart 额外开销分别计算，不能复用资料 50MB 常量。部署时仅对项目上传路径配置足够的 Nginx 请求体限额、临时磁盘和超时，资料与讨论仍保留原有 50MB 服务端校验。上传、解压和 GitHub 请求不同时累积整包的 Buffer / Base64 / JSON 副本；限制待处理包数量和临时磁盘总配额，超出配额时拒绝新上传并提示稍后重试；临时空间不足或客户端断开时提供明确失败提示并清理。

同步任务开始及发布前重新检查当前数据库中的账号状态、项目归属和删除状态。远端仓库默认私有，确认提交成功后才事务更新网站可见版本；中间失败可重试，新版本失败不得覆盖已发布版本。确认远端提交与本地记录完整后清理成功任务临时文件；失败和取消任务有有界清理策略，防止临时包长期积累。

GitHub 写请求由模块共享节流器串行安排，默认间隔 8 秒，避免 worker 每轮新建适配器重置节流。403 / 429 按 Retry-After、主限额重置时间和至少一分钟的冷却推迟后续写入。每份源码先流式校验 SHA256 并计算 Git blob SHA，读取已有对象确认存在后取消响应并复用，只有缺失才写入；部分同步失败或新版未改动的文件不重复上传。对 blob 的通用内容创建限额采用保守解释；真实接口仍可能限流，不能用模拟器结果保证远端无限可用。

临时目录默认 `data/project-tasks`，正式运行可指定独立持久路径。最多保留 2 个待处理任务目录，每个按 ZIP 与解包合计 400MB 预留配额，并保留额外磁盘余量。同步状态为 QUEUED / RUNNING / SUCCEEDED / FAILED / CANCELED；可重试的失败包最多保留 24 小时，过期与取消任务清理，上传后尚未入库的孤立目录按时限回收。已提交版本即使清理失败也保持成功，由下一轮补做清理。客户端长上传结束和 worker 发布前都再次检查会话 / 当前账号状态。

代码浏览、文件目录与版本包下载由网站重新检查成员权限后代理返回，使用 private/no-store，不把 GitHub 凭证或私有临时下载地址发送给客户端。下载尽量流式转发；所有仓库、版本和路径必须从服务器项目记录定位，不接受任意 GitHub URL。代码 / Markdown 采用转义的纯文本展示，文本预览最多读取前 1MB，二进制和不支持的文件给出下载提示；上传的 HTML、SVG 或脚本不得以可执行页面呈现。

公开项目 DTO 只包含显式允许的介绍字段，不包含邮箱、远端凭证、私有源码或讨论。新增模型和迁移应兼容既有资料、附件、成员与备份。部署说明须明确：本地备份包含项目元数据，GitHub 源码需要另外导出或备份，恢复时核对仓库与提交 SHA；不得声称本地备份已包含远端源码。

### PDF 问题的文件与页码绑定

按页问题的锚点包含 resourceId、fileId、page；绑定当前可访问的具体 PDF 文件。`ResourceComment` 新增可空的 pdfFileId、pdfPage、resolvedAt，旧普通评论保留空锚点，查询时不混入按页问题。`pdf-questions.ts` 统一检查成员、资料所属文件、PDF 类型和页码；回复在事务内继承父问题的文件 / 页码，而不是采用客户端声明。问题图片继续使用现有私有附件入口，并额外检查所绑定文件仍然可访问。

`pdf-pages.ts` 在独立 Node 子进程用 PDF.js 验证真实页数，文件不超过原资料 50MB，允许范围为 1–10000 页；子进程堆上限 128MB、15 秒超时、禁止字符串代码生成，不渲染、不执行 PDF 内容。解析任务串行、有界排队，并按文件键、大小和修改时间缓存可信结果。无法验证时返回中文错误，不相信客户端总页数，也不直接放行问题创建。解析完成后再次检查账号和文件状态。

PDF 阅读器提供当前页状态和跳页交互，问题列表、发布、回复及解决状态由单独的讨论业务能力处理；阅读器翻页不改变既有问题的锚点。回复继承父问题锚点，不允许通过提交另一个 fileId 或 page 将回复移到别处。普通讨论、按页问题和图片访问共享当前成员及父内容删除检查。

标记解决 / 重新打开仅提问者或管理员可操作，普通成员不能修改他人的状态。当前页与全部问题接口先授权再查询，响应 no-store；删除资料、问题或父回复后，讨论及媒体入口必须同时拒绝旧地址。
