# 2026-10-10：预览、多图资料与讨论图片升级

本地代码与服务器是两份独立副本。此升级包需要传到原服务器后运行，才能更新线上网站。

## 功能

- 文件预览与下载同权限，访客、待审批、未验证及停用账号不能读取内容。
- 图片原图预览；PDF 使用站内 Mozilla PDF.js，可翻页、缩放和查看本页文字；TXT/MD 纯文本预览。
- DOCX 正文和表格、XLSX 工作表与单元格内容、PPTX 幻灯片文字、ZIP 目录。保留内容，排版以原文件为准。旧 DOC/XLS/PPT 暂需下载或转换成现代格式/PDF。
- 一份资料可上传一份文档/ZIP，或最多 20 张图片，总量不超过 50×1024×1024 字节。
- 帖子、评论及两层回复可附图片；每条内容最多 20 张、总计 50MB。帖子编辑可删旧图、加新图，限额包含保留的旧图。

## 原服务器条件

AlmaLinux 9，Node 24、npm 11.19，systemd 服务 zhiye，项目 /opt/zhiye，私有数据库与上传目录位于 /var/lib/zhiye，至少 2GB 空余磁盘。沿用原 SMTP 和实际网站地址。Nginx 现有上传限制 60m 可继续使用。

新增迁移 20261010000000_media 只增加附件表，主文件和账号记录不重写。升级脚本先在独立目录安装、生成客户端和构建，期间旧网站继续工作；随后短暂停站备份、执行迁移，再切换到新版本。保留旧代码与备份；失败时尝试切回旧代码并重新启动原服务。数据库迁移是增加表，旧代码可继续读取原记录；如迁移失败，仍需根据日志修复失败的迁移记录再重试。

脚本仅处理 zhiye 项目和服务，不修改 Nginx、证书、firewalld 或 3x-ui。不会运行初始化 seed，也不会重置管理员密码。

## 上传（Windows PowerShell）

```powershell
$serverIp = Read-Host "请输入服务器公网 IP 或 SSH 主机名"
scp ".\releases\zhiye-source-20261010.tar.gz" ".\releases\zhiye-source-20261010.tar.gz.sha256" ".\scripts\upgrade-server-media.sh" "root@${serverIp}:/root/"
```

## 升级（服务器终端）

```bash
bash /root/upgrade-server-media.sh
```

准备依赖和构建可能需要几分钟。完成后显示 active 及 Upgrade complete。访问网站上传两张图片、预览文档、发带图帖子和回复，确认原有登录和资料下载仍正常。

## 数据与回退

升级前备份在脚本输出的旧代码目录下 backups/<时间>。另行保存原 .env 和整个备份目录到本机；不要将 .env 发到聊天中。

升级后 /opt/zhiye 是指向新版本的软链接，systemd 使用原路径继续启动。原数据库和私有文件仍在 /var/lib/zhiye。新脚本备份默认检测本地 127.0.0.1:3000，避免公网 Nginx 仍运行时误报网站未停止；自定义本地端口可设置 BACKUP_APP_URL。

需要人工回退时，先停站，核对脚本输出的 previous 路径；仅在 /opt/zhiye 确认是指向新版本的软链接时移除链接，再将 previous 路径移回 /opt/zhiye 并启动。旧代码可以读取添加表后的数据库，但不会显示新附件；不要在回退后继续发布内容再直接覆盖数据库备份。只有必须恢复数据库时才使用升级前数据库与文件的一致性备份，恢复会丢弃备份后的新数据。

## 本地开发

新增 fflate、pdfjs-dist 固定版本并提交到锁文件。PDF 阅读器代码、Worker、字体、CMap 与 WASM 都由本项目提供，不使用第三方在线文档服务。npm run dev/build 会准备 public/vendor/pdfjs 静态程序文件（不包含用户资料）。测试同样准备这些文件，源代码压缩包不携带生成副本。
