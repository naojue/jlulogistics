# 邮件排查与服务器账号恢复

## 邮件为什么没有收到

找回密码页面的成功提示是统一提示，避免泄露某个邮箱是否注册；它不保证邮件已成功送达。日志中的 `EAUTH`、`responseCode: 535` 表示 SMTP 发件账号认证失败。这发生在投递前，不能据此归因于超级管理员邮箱与发件邮箱相同。

QQ 发件配置使用 `smtp.qq.com`、端口 `465`、`SMTP_SECURE="true"`，`SMTP_USER` 为完整的发件 QQ 邮箱，`SMTP_PASSWORD` 为该邮箱开启 SMTP 后生成的授权码。授权码属于对应的发件邮箱，不是 QQ 登录密码。修改配置后重启网站进程。不要把授权码、完整配置或重置链接贴到聊天、截图、日志或源码仓库中。

在项目根目录运行 `npm run mail:check` 检查连接和认证。工具只连接 SMTP 并验证身份，不发送邮件；只输出安全的错误分类、响应码与中文处理提示。认证通过后仍须从网页再次申请重置，并检查收件箱和垃圾邮件；该检查不能保证发件人被接收或最终投递。

参考：[Nodemailer 错误分类](https://nodemailer.com/errors)、[SMTP 认证检查](https://nodemailer.com/smtp)、[腾讯云关于 QQ 邮箱授权码的说明](https://cloud.tencent.com/document/product/1270/55456)。

## 现有 AlmaLinux 服务器的离线恢复

适用于本项目的单实例部署：`/opt/zhiye`、数据库 `/var/lib/zhiye/community.db`、服务 `zhiye` 和可选的 `zhiye-project-worker`。如果数据库地址或服务名不同，先调整维护脚本再执行。确认数据库是正式站点当前使用的数据库，不要在旧发布目录或备份中运行。

将以下两个文件放到现有项目的 `scripts` 目录中，无需重新安装依赖或构建网站：

- `scripts/reset-super-admin.mjs`
- `scripts/reset-super-admin-server.sh`

在服务器的 root SSH 交互终端执行：

```bash
bash /opt/zhiye/scripts/reset-super-admin-server.sh
```

终端会提示输入两次 10–128 位的临时新密码，输入时不显示字符。不要把密码写入命令参数、环境变量或聊天消息。按 Ctrl+C 可取消；退出时恢复原先运行的服务。

成功后用工具显示的超级管理员邮箱和临时新密码登录，按页面要求再次修改密码。旧会话和旧密码重置链接已撤销；成员账号、资料、帖子、项目、账号权限均保持原样。初始化 `.env` 中的旧密码不会覆盖本次设置，重复执行初始化程序也不能用于恢复密码。

工具仅允许唯一、ACTIVE、已验证且恰好有一个 credential 密码账号的超级管理员，拒绝通过改密绕过审批或停用状态。发生事务失败时密码、会话、令牌和审计一同回滚；备份失败时不修改账号。

修改前会在 `/var/lib/zhiye/account-recovery/recovery-.../community.db` 保存数据库备份，目录和文件采用私有权限。它包含恢复前的账号数据与密码散列，不上传 GitHub、不对外分享。该恢复点只有数据库，不替代数据库和私有文件的一致性备份；成功后无需恢复。失败后不要盲目覆盖当前数据库，以免回滚其他用户的新内容。

本工具只修改服务器维护入口。网页审计中的中文操作名称需随下次完整网站升级部署；旧版本仍可显示操作代码。邮件诊断命令及安全日志修改也需将对应脚本与 `src/lib/mail.ts` 随完整版本部署。
